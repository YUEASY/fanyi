# 需求讨论决策

仅记录用户已确认的决定；未决项不代表默认批准。本文是需求讨论记录，不是 ADR。

## 已确认

- Q1：MVP 高亮全部符合规则的潜在生词，使用较淡的黄色下划线。
- Q2、Q6：普通释义先查本地词典，缺词时自动查询在线词典；断网且本地无结果时显示“未找到释义”。LLM 只由用户主动触发。
- Q3：生词本允许保留已掌握的词，并允许删除条目。
- Q4、Q7：用户输入网址启用网站，范围为完整域名。例如输入 docs.github.com 下的页面网址后覆盖该域名全部页面，不覆盖 github.com 或其他子域名。设置页支持删除启用网站。
- Q5：第一版供用户本人学习使用。
- Q8：删除生词本条目只取消收藏，不改变熟词状态。
- Q9：提供可搜索的熟词表并支持移除；生词本中的已掌握条目也能改为未掌握，两处同步改变熟词状态。
- Q10：生词本展示单词、收录时的中文释义和掌握状态；支持搜索、按掌握状态筛选及删除。MVP 不保存原句和来源网址。
- Q11、Q12：第一版必须完成 API Key 配置以及手动 LLM 单词、短语和专业术语翻译；采用 DeepSeek 官方直连，默认模型 deepseek-v4-flash，不增加第三方平台配置。未配置 Key 时，在点击 LLM 翻译时弹出提示并提供“前往设置”入口。
- Q13：LLM 请求包含目标单词或短语及其所在句子，不发送整个网页；生词本不保存原句。
- Q14：LLM 展示中文译文和一句简短技术解释，不显示音标、词性或自动生成的例句。
- Q15：没有有效中文释义时无法收藏；词典无释义时，需要 LLM 翻译成功后才可收藏。收藏时优先保存已有 LLM 结果，否则保存普通词典结果；后续翻译不自动覆盖收录释义。
- Q16：选择英文后显示小型翻译按钮，点击打开浮层，再主动点击“专业术语翻译”调用 LLM；第一版短语只用于翻译，不加入生词本。
- Q17：首次初始化导入 google-10000-english 前 1500 词作为初始熟词，之后允许逐个移除，重启不补回。可可靠还原的词形共享掌握状态，无法确定的按独立单词处理；浮层显示归一后的管理对象，例如“按 work 管理”。
- Q18：无释义时仍允许点击“认识”；“加入生词本”不可用，并提示“请先完成翻译”。
- Q19：词典查无结果显示“未找到释义”；请求失败显示明确原因和重试按钮。LLM 失败时保留已有词典释义，不自动重复调用。
- Q20：未启用的网站不扫描、不高亮、不出现浮动入口，也不允许手动翻译。
- Q21：已打开页面之间的掌握状态及网站启用状态尽量立即同步，前提是不产生明显性能问题；立即同步不是第一版验收门槛。原需求中的当前页面标记认识后取消同词高亮、刷新后状态持久保留仍然有效。
- Q22：可可靠归一的不同词形在生词本中只保留一个原形条目；再次遇到显示“已加入生词本”，不重复收藏或覆盖原释义。
- Q23：代码区域全部跳过；正文中跳过明显代码标识，如 useState、foo_bar、user123；HTTP、DeepSeek 等缩写或名称仍按熟词表判断，允许手动标记认识。
- Q24：单词走词典流程；多个单词组成的短语只提供手动 LLM 翻译。打开短语浮层时显示原文和翻译按钮，不自动发送请求。
- Q25：普通词典释义可以复用；LLM 结果只在目标文本与上下文都相同时复用，新语境仍先显示普通释义，由用户主动调用 LLM。生词本保留收录时的释义。
- Q26：熟词表、生词本、启用网站和 API Key 保存在当前浏览器插件的本地存储中，重启后保留。Key 可替换、删除，设置页默认遮罩显示。第一版必须支持导入导出。
- Q27、Q28、Q29：导出文件采用带版本号的单个 JSON，包含熟词表、生词本、启用网站及非敏感设置，不包含 API Key。导入只支持完全替换，不提供合并；导入不会修改当前浏览器中已有的 API Key。文件无效或版本不受支持时整次拒绝，不允许部分导入。
- Q30：完全替换导入前展示数据摘要及覆盖警告，并要求用户确认；不自动导出或保存替换前的旧数据备份。导入完成后不删除用户选择的 JSON 文件。
- Q31：MVP 导出结构不设置含义模糊的通用 `settings` 字段，只包含格式版本、熟词表、生词本和启用网站；API Key 不导出。未来新增明确的非敏感设置时再升级格式版本。
- Q32：三个数据集合均为空的备份仍是合法备份，可以完全清空当前的熟词表、生词本和启用网站；确认界面必须明确提示该结果，API Key 保持不变。
- Q33：“不删除本地文件”指保留用户选择的 JSON 文件；插件本地存储中的旧熟词表、生词本和启用网站仍由导入数据完全替换。
